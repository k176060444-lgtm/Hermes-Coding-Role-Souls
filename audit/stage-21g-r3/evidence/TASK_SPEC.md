# TASK_SPEC 候选：Inventory CSV CLI（TEST_ONLY）

**状态：候选，未冻结，待调度端依据已批准实验需求核验并记录 TEST_ONLY 冻结。**  
**生产 Gate：未批准；本候选不构成生产规格、部署或外部盲审批准。**

## 1. 目标

在指定的本地 scratch Git 仓库中实现一个仅使用 Python 标准库的库存 CSV 汇总命令行程序，并提供真实 `unittest` 测试。

## 2. 已批准需求与范围

- 每条输入记录包含 `sku,delta` 两个字段。
- `delta` 必须是整数，可以为正数、负数或零。
- 相同 SKU 的 delta 累计。
- 成功结果按 SKU 排序。
- 字段数错误、空 SKU、非法整数必须报错。
- 无效输入不得产生或展示成功汇总，包括部分输入有效、后续记录失败的情况。
- 使用 Python 标准库，不引入第三方依赖。
- 程序、测试、夹具仅在本地运行；不联网、不读取生产数据、不调用外机、不部署生产。
- 使用指定实验仓库，不使用 Hermes/P1 生产源码。
- 仅当存在可复现缺陷时才触发模拟整改。

## 3. 非目标与禁止项

- 不实现生产库存接入、数据库、网络 API、认证、部署或外部系统集成。
- 不复用或改动 Hermes/P1 生产源码。
- 不把实验冻结、实验 Gate 或本地审查说成生产审批、正式外部盲审或部署授权。
- 不自行扩大用户批准的输入语义；尤其不得静默跳过坏行、将非法值当零或在失败后打印部分成功结果。

## 4. 流程

1. 调度端对照 USER_BRIEF 与 TEST_ONLY 授权审核本候选，并记录实验规格是否冻结。

本候选不指定角色执行身份、实际模型身份或额外调度授权。请求模型为 `group/gpt-6-luna`；`observed_model=UNVERIFIED`（当前没有服务端绑定证据）。

## 5. 模块与边界

当前仓库只有需求与授权文档，没有既有业务模块。以下为拟建职责，实施者可用最少文件实现：

- CLI：选择输入来源、协调处理、将成功结果或错误反馈给调用者。
- CSV 校验：逐记录检查字段数、SKU 和整数 delta。
- 汇总：累计 SKU 数值并按 SKU 排列。
- 测试：使用标准库 `unittest` 验证公开可观察行为。

CLI 文件/标准输入的选择、命令参数和模块文件名均未定；不得因此改变已批准的输入及汇总规则。

## 6. 数据、规则与状态

- 记录：`sku` 为非空字符串；`delta` 为可解析的整数。
- 累计值：每个 SKU 对应其全部有效记录 delta 的整数和。
- 输出状态只有成功与失败：仅全部输入校验通过后才能产生成功汇总；任一输入错误则整体失败。
- 成功顺序：按 SKU 字符串排序。排序比较规则按 Python 字符串默认顺序处理；若需求审查认为需要其他规则，须先确认，不可擅自调整。
- 输入的表头要求、编码、空行处理、重复表头行为和空文件语义尚未规定，不可把建议冒充用户原始要求。

## 7. 异常处理

- 字段数不是 2：报告输入错误，整体失败。
- SKU 为空：报告输入错误，整体失败。
- delta 不能解析为整数：报告输入错误，整体失败。
- 任一错误发生时，不输出汇总数据或“成功”标记；允许输出指明失败原因的诊断信息。
- 建议将诊断写至标准错误流并以非零状态结束；具体错误文案与退出码属于待确认实现细节。

## 8. 验收条件

1. 标准库环境即可运行，项目无第三方运行依赖。
2. 至少两条同 SKU 记录正确相加，正负值均覆盖；可验证零值行为。
3. 多 SKU 成功输出按 SKU 排序。
4. 字段缺失或多余、空 SKU、非法整数各自有失败测试。
5. 包含有效行后再遇到错误行时，确认没有部分汇总或伪成功输出。
6. 测试由标准库 `unittest` 执行，失败测试能在缺陷存在时失败，修复后通过。
7. 记录实际测试命令、退出码和对应固定提交；不得用手写 PASS 替代执行证据。
8. 无网络、生产数据、外机、部署或第三方依赖使用。
9. 实验报告明确区分 TEST_ONLY 结果与生产 Gate；后者保持未批准。
