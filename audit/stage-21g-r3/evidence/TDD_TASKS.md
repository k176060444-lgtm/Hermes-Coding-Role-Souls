# TDD 原子任务候选

**状态：候选，依赖 TASK_SPEC 经调度端检查并记录 TEST_ONLY 冻结后执行。**  
每项约 2–5 分钟；由获授权实现者按顺序完成。命令需按最终选定的 CLI 接口调整，并在实验记录中保留实际命令与退出码。

## 任务 1：定义最小有效输入和排序

- 输入：冻结后的输入入口决策、两 SKU 的有效 CSV。
- RED：添加测试，断言结果包含各 SKU，且按 SKU 排序；运行测试，确认尚无实现时失败。
- GREEN：添加最小成功路径，使该测试通过。
- REFACTOR：移除重复处理，只保留必要逻辑。
- 交付/完成：成功路径测试真实运行；测试先失败、实现后通过。
- 失败检验：测试若在实现前通过，检查是否误测固定输出或调用了旧实现。

## 任务 2：同 SKU 正负累计

- 输入：同一 SKU 的正、负 delta 记录。
- RED：添加测试，断言同一 SKU 汇总为正确整数和。
- GREEN：实现累计，使测试通过。
- REFACTOR：保持累计逻辑简洁，无重复状态。
- 交付/完成：可验证负值被正确相加，而非忽略或取绝对值。
- 失败检验：故意用错误预期确认测试会失败，再恢复正确预期。

## 任务 3：字段数校验

- 输入：缺字段和多字段的记录样例。
- RED：分别添加失败测试，断言程序报错且不产生成功结果。
- GREEN：实现字段数检查。
- REFACTOR：统一错误处理路径。
- 交付/完成：两类记录均失败；有效前缀后接坏行也没有部分汇总。
- 失败检验：测试检查 stdout 不含汇总或成功标记，且退出状态失败（若退出码规则已冻结）。

## 任务 4：空 SKU 校验

- 输入：SKU 为空的记录；空白字符边界遵从冻结决策。
- RED：添加空 SKU 错误测试。
- GREEN：实现经确认的空值规则。
- REFACTOR：避免把 SKU 处理与无关字段耦合。
- 交付/完成：空 SKU 明确失败，不输出汇总。
- 失败检验：检查只有诊断信息，没有部分成功输出。

## 任务 5：非法整数校验

- 输入：非整数 delta 记录。
- RED：添加非法整数失败测试。
- GREEN：实现整数解析和错误报告。
- REFACTOR：使错误信息保持一致且可理解。
- 交付/完成：非法输入失败，合法正负整数仍通过。
- 失败检验：确认非法值不会被替换为零或跳过。

## 任务 6：输入整体原子性

- 输入：先有效记录、后无效记录的 CSV。
- RED：添加端到端测试，断言失败且无任何成功汇总。
- GREEN：必要时改为先完整校验/累计、确认无错误后再输出。
- REFACTOR：清理可能在错误前写出的输出路径。
- 交付/完成：任意后续坏行都不能留下部分结果。
- 失败检验：以 stdout 捕获实际输出；检查失败状态和无结果。

## 任务 7：空输入与边界回归

- 输入：已冻结的空输入、表头、空行及 SKU 空白规则。
- RED：按最终明确决策补充对应测试。
- GREEN：实现决策要求的行为。
- REFACTOR：删除无用分支，保留清楚的输入约束。
- 交付/完成：边界行为有测试支撑；未决项不得默认为已批准。
- 失败检验：对每项边界构造与预期相反的实现，确认测试能检出。

## 任务 8：完整 unittest 验收

- 输入：实现提交及完整测试集。
- RED：确认至少一个关键断言在故意破坏对应行为时失败。
- GREEN：恢复实现并运行完整标准库测试。
- REFACTOR：整理测试名称和重复夹具。
- 交付/完成：记录真实命令、退出码、提交标识和输出证据；全套测试通过。
- 失败检验：测试执行失败或无法证明实际运行时，不报告通过，也不按 CLI 退出码单独放行。
